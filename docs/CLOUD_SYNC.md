# Optional local-first sync reference

Mavframe's browser-local profile is not a cloud identity. The optional connector signs in separately with Supabase Auth using the project's public anon key; it never accepts a service-role key. Access tokens stay in memory and are cleared on logout or page close. Local edits remain on this device until a user explicitly connects and presses Sync. No hosted provider is configured by default.

Only two collections are allowlisted: saved view settings and theme preferences. Capture bytes, decoded payloads, signed material, browser profile password verifiers and sessions are excluded. Requests omit credentials and referrers, have a 10 second deadline, and cap request payloads at 48 KiB and response bodies at 64 KiB. Sync compares revisions and returns a pending/conflict state; differing data is never overwritten without an explicit keep-local/upload or use-remote choice. Use-remote is staged for explicit local application. Revision checked RPCs prevent stale writes and deletes. Network or acknowledgement failures remain unsynced.

To configure a project you own, apply `SUPABASE_SYNC_SETUP.sql`, enable Supabase Auth, and provide the project URL and public anon key in the Account Settings sync form. Before publishing that configuration, add only its exact origin to the `connect-src` directive in `index.html` (for example `connect-src 'self' https://PROJECT-REF.supabase.co;`). The shipped policy allows same-origin requests only; it does not open arbitrary HTTPS destinations. Review the SQL, RLS policies and provider's retention settings yourself. `auth.uid()` plus forced RLS is the authorization boundary; client-side owner filters are not. This repository has no configured project, does not create cloud resources, and has not been verified against a real Supabase project. Local fake-service tests exercise the HTTP contract only; they do not prove deployed RLS or provider security. Sync is not end-to-end encrypted.
