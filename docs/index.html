Format help

What the inspector reads, how it decides a frame is good, and what it does not check.

What you can open

A .tlog file (each record is an 8-byte big-endian microsecond timestamp followed by one frame, as written by ground stations) or a raw byte stream of MAVLink v2 frames. Auto-detect picks .tlog from the file name or from a plausible timestamp before the first start byte. Captures up to 256 MB are read in this tab; the details of the first 4,000,000 frames and 100,000 issues are listed, and the counts always cover the whole file.

MAVLink v2 frame layout

Bytes of one MAVLink v2 frame
BytesFieldNotes
0Start byte0xFD for v2 (v1 uses 0xFE and is not parsed).
1Payload length0 to 255. Trailing zero bytes of the payload may be trimmed by the sender.
2Incompat flagsOnly bit 0 (signed) is supported; any other bit makes the frame a "bad flags" reject.
3Compat flagsIgnored.
4Sequence8 bits per sender, wraps at 255.
5–6System ID, component IDShown as sys:comp.
7–9Message ID24 bits, little-endian.
10…PayloadDecoded for HEARTBEAT, SYS_STATUS, GPS_RAW_INT, ATTITUDE, GLOBAL_POSITION_INT and VFR_HUD from the official XML.
+2CRCCRC-16/MCRF4XX over bytes 1 to the end of the payload plus the message's CRC_EXTRA byte.
+13SignatureOnly when signed: link id, timestamp, hash.

CRC failed, unsupported, bad flags

CRC failed: the header looked valid, but the checksum the parser computed does not match the two CRC bytes in the capture. The frame is discarded and the parser looks for the next start byte inside it, so a valid frame hidden in damaged bytes is still found. Frame details shows the wire and computed values side by side.

Unsupported: the message id is not in the common dialect, so its CRC_EXTRA is unknown and the checksum cannot be checked. It may come from another dialect (such as ardupilotmega) or be noise. These are never counted as corrupt.

Bad flags: incompat flags other than "signed", which this parser does not support.

Sequence gaps and the channel assumption

For each sender the step between sequence numbers is read as in order (1), duplicate (0), a gap (2 to 128: about step − 1 frames missing) or a step back (a late frame when small, otherwise a likely sender restart). A gap is an estimate: it assumes one fully observed channel per sender and in-order arrival. A late frame, a router that drops or filters messages, or two merged links look the same.

Signatures

Signed frames carry 13 extra bytes. The inspector shows them as "signature present; not verified": checking a signature needs the link's secret key, and the parser does not do it.

The bundled sample

The engineering sample (sample/sample-flight.tlog) is synthetic: tools/gen_sample_tlog.py generates it with known CRC failures, sequence gaps and skipped bytes so the tests can check exact counts. It is not a real flight and its numbers say nothing about any vehicle.

Finding export

Frame details can save one row as JSON: tool version, file name, size and SHA-256, offsets, CRC wire vs computed, the sequence note if any, and the assumptions above. All payload bytes are left out by default. The checkbox adds them when a full frame was retained; raw bytes may contain GPS/position or other sensitive data. Unsupported and bad-flags candidates retain only a header, so their payload and CRC are unavailable.
